# 主管自动准备与补充尝试（0.3.3）

本文件描述的修复包含在 0.3.3 Apple 芯片 Mac 安装包中。

画像确认后，主管检查必填信息、主管/调研员/数据师的模型连接、已配置的判断模型和预算。准备过程显示在任务管理页。首次确认或升级后恢复已确认画像时，系统只排入一次准备工作；检查通过后立即安排第一轮任务，后续按客户的每日时间运行。

来源池为空时，主管提出最多 5 个公开来源入口。网址只是候选，必须由爬虫读取到相关内容后才入池。无法验证任何来源时，任务不启动，并显示失败原因。主管保留客户目标、预算、重试次数与每日时间，不降低线索判定标准。公开网页无需先登录社交账号；私有来源仍使用客户自己的登录和可访问范围。

单次任务和每日计划可设置 0～3 次追加尝试。每次未达目标后，主管先提出不同入口、验证真实内容并补充来源池，再重新检查准备条件，安排剩余目标。已有合格线索累计计入目标。暂停、预算不足、取消或没有验证成功的新来源时停止，不把空重跑记成完成目标。重启时使用已记录的计划与父任务关系避免重复派发。

爬虫使用 Scrapling 0.4.15。普通页面先 HTTP 抓取；专用版自动检测 JavaScript 页面并使用 DynamicFetcher；已有 StealthyFetcher 用于允许的一次浏览器检查回退。普通 HTTP 请求采用文档默认的浏览器请求头。浏览器未就绪时记录为待处理，不把空 JS 壳当作有效内容。robots、限速、页数和预算限制保留。

这轮也开启桌面窗口文字选择，并添加每条消息的复制、单条删除。删除单条消息保留其他消息与备忘录；迟到的回复不会把已删除上下文重新写回来。

诊断依据：客户上传的 0.3.2 包中，任务 20261015-045514-c1e3 以 search_blocked 失败，pages/pool/processed/qualified 都为 0。免费搜索各入口失败详情被深度限制截断，网页源未收到起始网址，YouTube 来源也回到同一搜索入口。根因在入口发现阶段；这份证据不能用于认定关键词过滤或数据师筛选失败。
